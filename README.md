# AI Compass — פלטפורמת כשירות AI (MVP)

גרסת פיילוט ראשונית לתלמידים ולמורים, בעברית ובערבית.

פלטפורמה למגמת **הנדסת אלקטרוניקה ומחשבים**: התלמיד מגבש הצעת פרויקט בשיחת חקר עם מנחה AI, והמורה רואה את הדרך ומעריך את רמת כשירות ה-AI.
🌐 האתר: https://ai-competency-platform.onrender.com · 🧭 המסגרת הפדגוגית: https://ai-competency-platform.onrender.com/framework

## איך מנחה ה-AI מוביל את התלמיד לכשירות AI
המנחה **לא כותב את הפרויקט במקום התלמיד**. הוא מקבל בכל הודעה הנחיה שנבנית מפרופיל הבוגר של המגמה ([`competency.py`](competency.py)), ומכוון את התלמיד ל**רמה 3 – משלב/מטמיע**: לתכנן ולשלב רכיב AI במערכת משובצת, לזהות כשל בפלט, לבצע תיקון מנומק ולאמת אותו במדידה.

| התלמיד כותב | מה המנחה עושה | הכשירות שמתורגלת |
|---|---|---|
| "אני רוצה בית חכם" | לא נותן פתרון; שואל מה הבעיה, מי המשתמש ומה האילוצים | ניסוח בעיות |
| "אורות נשארים דלוקים בכיתה" | מבקש להשוות שתי חלופות (למשל חיישן PIR מול מצלמה) | פתרון יצירתי |
| "אשתמש במצלמה עם AI" | שואל איך ה-AI מתחבר לחיישן, לבקר ולממסר, ומה קורה כשהמודל טועה | חשיבה מערכתית · אוריינות AI |
| "ה-AI כתב לי קוד" | שואל איך יבדוק שהקוד נכון (מדידה, לוג, ניסוי) ומזכיר לתעד ביומן | אחריות מקצועית ואימות |
| "תכתוב לי את ההצעה" | מסרב בנימוס, נותן רמזים ומבקש לנסח לבד | עבודה עצמאית |

**התהליך המלא:**
1. **התלמיד** חוקר ומנסח בעצמו; ה-AI הוא מנחה, לא כותב.
2. **המורה** רואה את כל השיחה, סימנים ראשוניים לכל אחת מחמש הכשירויות, ומדריך רמות — ו**קובע את הרמה בעצמו** לפי הראיות.
3. **היעד:** שהתלמיד יגיע ל"משלב/מטמיע" — מחבר AI למערכת, בודק, מתקן ומאמת במדידה.

> אלה הנחיות למודל שפה, לא חוקים קשיחים: לרוב הוא פועל כך, אך עלול לסטות. לכן המורה רואה את כל השיחה, ואין ציון אוטומטי.

### חמש כשירויות הליבה של הבוגר
1. חשיבה מערכתית הנדסית · 2. אוריינות AI ונתונים · 3. ניסוח בעיות ופתרון יצירתי · 4. אחריות מקצועית ואתיקה · 5. עבודת צוות וניהול פרויקט

### רמות הכשירות
| רמה | שם | בקצרה |
|---|---|---|
| 1 | משתמש | משתמש בכלי לפי הנחיה ומקבל את התשובה כפי שהיא |
| 2 | מיישם | מנסח בקשה מדויקת, מתאים את התוצר לפרויקט ובודק — הבסיס לרמה 3 |
| **3** | **משלב/מטמיע (יעד)** | מחבר רכיב AI לחיישנים, לבקר ולמפעיל, בודק תוצאות, מתקן ומאמת במדידה |
| 4 | יוצר/חוקר | מפתח/מאמן רכיב AI משלו וחוקר חלופות באופן שיטתי |

כל הטקסטים האלה — כולל ההנחיה המלאה למנחה בעברית ובערבית — נמצאים ב-[`competency.py`](competency.py). לשינוי התוכן עורכים רק את הקובץ הזה.

## מה עובד בגרסה זו
- רישום וכניסה לתלמיד ולמורה; שיוך תלמיד למורה באמצעות דוא״ל.
- שיחת חקר עם Gemini (עם ניסיונות חוזרים ומודלים חלופיים בעומס), עם הדרכה לשיפור פרומפטים ולא רק מתן תשובות.
- שמירת היסטוריית השיחה במסד נתונים.
- עריכת הצעת פרויקט, שמירת טיוטה והגשה.
- ממשק מורה לצפייה בתהליך, הערות, אישור והערכת רמה 1–4 ידנית.
- סימני חקר ראשוניים המבוססים על מילות מפתח — **לא** מדידת כשירות תקפה או ציון אוטומטי.
- מעבר עברית/ערבית.

## מה עדיין לא קיים
- מחוון כשירות מאומת והערכה אוטומטית מבוססת ראיות, גרפים לאורך זמן, יצירת הצעה אוטומטית מתוך השיחה, ייצוא PDF/Word, ניהול כיתות מתקדם, צוותים זוגיים, תבנית הצעה מקורית מאושרת, שחזור סיסמה, אימות דוא״ל, הגבלת קצב, בקרות פרטיות מתקדמות ומוכנות לפריסה עם קטינים.
- תהליך השיחה אינו כולל כרגע משימות הערכה מובנות; המורה הוא שקובע רמה.

## GitHub + Render
1. צור מאגר GitHub פרטי והעלה אליו את קובצי התיקייה **בלי .env**.
2. ב-Render צור PostgreSQL ו-Web Service המחובר למאגר.
3. Build command: `pip install -r requirements.txt`
4. Start command: `gunicorn app:app`
5. הגדר Environment Variables:
   - `SECRET_KEY` מחרוזת ארוכה אקראית
   - `GEMINI_API_KEY` מפתח **חדש** שלא נחשף בצ'אט
   - `GEMINI_MODEL` למשל `gemini-3.8-flash` (כפוף לזמינות בחשבון)
   - `DATABASE_URL` כתובת החיבור הפנימית של PostgreSQL
   - `COOKIE_SECURE=true`
   - `ALLOW_TEACHER_SIGNUP=true` זמנית בלבד בעת הקמת המורה הראשון
   - `TEACHER_INVITE_CODE` קוד פרטי חזק
6. צור חשבון מורה ראשון ואז שנה `ALLOW_TEACHER_SIGNUP=false`. תלמידים נרשמים באמצעות דוא״ל המורה.
7. בדוק את `/health` ואת תהליך הכניסה, הצ'אט והמשוב.

**חשוב:** אין להסתמך על SQLite בדיסק זמני של Render; השתמש ב-PostgreSQL לשמירת נתונים. אל תחשוף מפתחות בקוד, בדפדפן או בצ'אט.

## בטיחות, פרטיות והפעלה חינוכית
המערכת מיועדת **להדגמה עם חשבונות בדיקה פיקטיביים בלבד** בשלב זה. לפני הכנסת נתוני קטינים נדרשים אישורי המוסד/הרשות, מדיניות שמירה ומחיקה, אימות הרשאות, הגבלת בקשות, בדיקות אבטחה, תיעוד הסכמה ככל שנדרש, ומחוון כשירות פדגוגי מתוקף. אל תזין מידע רגיש לצ'אט AI.

## הערכת כשירות
כל התוכן הפדגוגי נמצא בקובץ אחד: **`competency.py`**. כדי לשנות מה המערכת מלמדת ומחפשת, עורכים רק אותו.

- **פרופיל הבוגר** של מגמת הנדסת אלקטרוניקה ומחשבים: מטרת־העל וחמש כשירויות הליבה (חשיבה מערכתית הנדסית, אוריינות AI ונתונים, ניסוח בעיות ופתרון יצירתי, אחריות מקצועית ואתיקה, עבודת צוות וניהול פרויקט).
- **רמות הכשירות 1–4**: (1) משתמש, (2) מיישם, (3) משלב/מטמיע — **רמת היעד**, (4) יוצר/חוקר. רמות 2–3 לקוחות ממסמכי המגמה (כשירות AI מתקדמת, אירוע הערכה 2026); רמות 1 ו-4 הן טיוטת עבודה לאישור הפיקוח.
- **ההנחיה למנחה ה-AI** (`system_prompt`) נבנית אוטומטית מהפרופיל ומרמת היעד, בעברית ובערבית.
- **סימנים ראשוניים למורה** (`preliminary_evidence`): לכל כשירות מוצגות המילים שנמצאו בשיחה. אלה רמזים בלבד — **המורה קובע את הרמה**, אין ציון אוטומטי.
- עמוד **`/framework`** מציג את המסגרת המלאה (פרופיל, רמות, הבחנה פדגוגית) — מתאים להצגה לפיקוח.
